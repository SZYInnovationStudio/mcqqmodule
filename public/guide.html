使用教程

按顺序做，就能用

先连接 MC 和 QQ 官方 Bot，再让群友自己登记和绑定。

去修改信息
01

准备 MC 服务器

记下服务器游戏地址和端口。在 server.properties 开启 RCON，设置端口、强密码，保存后重启。

enable-rcon=true
rcon.port=25575
rcon.password=你自己设置的强密码

RCON 用来发送 AQQBot 绑定命令。不要直接把 RCON 端口开放到公网。

02

准备 QQ 官方 Bot

在 QQ 开放平台创建机器人，取得 AppID 和 AppSecret，填到「修改信息」。把机器人加入目标群，启用群消息相关权限。

先保存 Bot 凭证；在群里 @机器人发一条消息，到总览“操作记录”复制发现的群 OpenID，再填到“允许使用的群 OpenID”。可以填多个，用逗号分隔。

本平台的 QQ 接入使用官方 Bot，不使用 OneBot。但现有 AQQBot 插件本身可能仍依赖 OneBot 后端；请先确认它在 MC 服务器上能正常接受控制台命令。

03

保存并测试

打开「修改信息」，点“保存信息”，依次测试 RCON 和 MOTD。回到总览确认 QQ 机器人显示“已连接”。管理员还可打开独立的「RCON 终端」，先发送 list 查看命令回复。

要开启 MC → QQ，还需填写 MCSManager 面板地址、API Key、Daemon ID 和 Instance UUID，保存后点“测试 MC 控制台”。请让一名玩家在游戏里发话，再检查测试结果的 detectedChats 是否出现玩家名和消息。若没有，先别开启 MC → QQ。API Key 留空不会清除已保存的值，不要在群里发送密钥。

打开 RCON 终端
04

群友登记 QQ 号

在允许的群中 @机器人发送 /qqbind 36000000（换成自己的 QQ 号）。机器人回显该号码并给出 BIND-XXXXXX 确认码；本人核对号码正确后，在同群 5 分钟内 @机器人直接发送收到的码，即自动登记，不需要管理员审核。

只有 /qqbind 不要求先登记。其他业务命令未登记时只提示先绑定 QQ，确认后请重新发送原命令。二次核对不验证数字 QQ 号的归属。
05

绑定或解绑 MC 玩家

登记后，群友 @机器人发送 /mcbind implayer，其中 implayer 是自己填写的 Minecraft 玩家名。一个 QQ 可以登记多个玩家。平台通过 RCON 执行：

aqqbot whitelist bind <qq> <player>

<qq> 会填成已登记 QQ 号，<player> 会填成玩家名；实际发给服务器时不带尖括号。解绑单个玩家发 /mcunbind implayer，平台只向服务器发送 aqqbot whitelist unbind name <player>；/mcunallbind 会对自己名下的玩家逐条发送同一种解绑命令。不会修改 MC 服务器配置。

06

全部 QQ 命令

/qqbind <数字QQ号>       首次登记，例如 /qqbind 36000000
/qqunbind                无 MC 玩家后解除 QQ 登记
/mcbind <玩家名>         绑定一个 MC 玩家
/mcunbind <玩家名>       解绑自己名下的一个 MC 玩家
/mcunallbind             逐条解绑自己名下的全部 MC 玩家
/motd                    查询服务器介绍、在线人数和在线玩家名
/list                    只显示当前在线玩家名

在 QQ 官方 Bot 的指令配置里添加 qqbind、qqunbind、mcbind、mcunbind、mcunallbind、motd、list 七个名字。若输入框已经自带 /，不要重复输入。机器人生成的 BIND-XXXXXX 只作为本人二次确认消息，不是固定指令。

07

原有方式：RCON / MCSManager 聊天

网页有两个独立开关。QQ → MC：官方 QQ Bot 收到允许群的普通消息，在原有方式下平台通过 RCON 把它显示到游戏里；默认只把 [群名称] 标成绿色，成员名和消息保持默认颜色。这个方向只需 QQ Bot 和 RCON。

官方 Bot 的群消息只有群 OpenID 和发送者账号昵称，没有 QQ 界面中的群名称、群名片。若想显示真实名称，在“修改信息”的“群名称”里填 群OpenID=想显示的群名；若要把 Bot 昵称改成群名片，在“成员显示名”里填 成员OpenID=想显示的名字。每条一行。群 OpenID 可从允许群列表复制；成员 OpenID 在首次发言后从总览操作记录查找。

MC → QQ：平台每两秒读取一次 MCSManager 实例的控制台输出，只识别新出现的玩家聊天，再推送到允许群。这个方向需要 QQ Bot、MCSManager API Key、Daemon ID 和 Instance UUID；必须先测试控制台确实能看到玩家聊天。若测试显示管理员禁用 API Key，请联系面板管理员启用 enableApiKey 并重启面板 Web 服务，网页无法绕过这个限制。腾讯 QQ Bot 的主动推送可能受额度限制。

两个模板可在“修改信息”编辑：QQ → MC 默认 &a[${groupName}]&r ${userName}：${message}，MC → QQ 默认 [服务器] ${player}: ${message}。平台不会修改服务器里的 AQQBot 配置或消息文件；如果 AQQBot 本身也在转发聊天，服主需要自行关闭对应方向，避免重复。

08

管理用户与查看日志

管理员打开“已绑定用户”页面，可查看、修改和删除本平台记录。修改或删除本平台记录不会自动改动服务器 AQQBot 的实际白名单；需要时请在服务器端另行同步。“玩家日志”页面按命令类型查看 QQ 玩家操作和处理结果；“RCON 终端”单独保存管理员手动发令日志。

09

推荐：双向聊天改走独立插件

把 szydmc-chat-bridge-1.0.0.jar 放进 Paper / Purpur 服务端 plugins/ 并重启。网页“修改信息”里生成插件 Key，复制到插件生成的 plugins/SZYDMCChatBridge/config.yml 的 key，再重启 MC。插件默认连接同机 127.0.0.1:2556；若程序不在同一台机器，先建立安全隧道。

随后在网页把“聊天接入方式”切为“独立插件”，按需开启 QQ → MC 与 MC → QQ，保存并点“测试插件连接”，确认显示 connected: true。这两个方向都不再使用 RCON 或 MCSManager API；现有玩家白名单绑定仍继续使用 AQQBot 和 RCON，不会同步或覆盖旧白名单。
